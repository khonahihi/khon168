# KHON168 Photobooth REST API v1

Base URL: `http://127.0.0.1:4000` on your own computer. For iPhone/production testing, use HTTPS and a configured public origin.

| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | Health status |
| GET | `/api/photobooth/frames` | Built-in frames and aliases |
| POST | `/api/photobooth/sessions` | Start 4-shot session. JSON `{ "frameId": "school" }` |
| GET | `/api/photobooth/sessions/:uuid` | Read progress |
| POST | `/api/photobooth/sessions/:uuid/shots` | Upload one image; multipart field `image` or JSON imageBase64 |
| GET | `/api/photobooth/sessions/:uuid/preview` | Preview JPEG after 1, 2, 3 or 4 shots |
| DELETE | `/api/photobooth/sessions/:uuid` | Discard session and its photos |
| POST | `/generateFilteredImage` | Experimental JSON adapter for intercepted Locket requests |

## Sample create session

```sh
curl -X POST http://127.0.0.1:4000/api/photobooth/sessions \
  -H 'Content-Type: application/json' \
  -d '{"frameId":"school"}'
```

Response includes an unguessable session UUID generated by the server.

## Upload a picture

```sh
curl -X POST http://127.0.0.1:4000/api/photobooth/sessions/REPLACE_SESSION_UUID/shots \
  -F 'image=@photo1.jpg'
```

The response includes `shots: 1` and a `previewUrl`; after the fourth photo, `complete: true`.

## Experimental adapter

```json
{
  "filter_id": "back_to_school",
  "imageBase64": "<BASE64_ENCODED_JPEG>"
}
```

Required header: `X-KHON168-Session: <UUID>`. Alternative `X-KHON168-Frame` specifies frame ID. Response includes compatibility-oriented `result.outputUrl`, `result.output_url`, `result.imageUrl`, `result.image_url`, `result.url` and `complete`.

These names are **best-effort guesses**, not an authenticated live Locket contract. The adapter recognizes only configured aliases; it does not guess unknown fields.

Use `DELETE` to dispose of an unfinished session. Sessions expire after `SESSION_TTL_MINUTES`; cleanup happens at startup in this prototype.
